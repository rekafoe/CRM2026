# Warehouse Quarter Foundation

## Цель квартала

Свести склад, списания и аналитику к единому контуру данных без ломки текущих заказов и калькуляторов.

## Архитектурные принципы

- Единый источник движений: все приходы/списания/корректировки идут через `MaterialTransactionService`.
- Единый источник отчетов: `material_moves` + `materials` + `material_stock` без дублирующих расчетов в разных сервисах.
- Оценка склада и себестоимость движений: `materials.purchase_price` (fallback на `sheet_price_single` для legacy). Отпускная цена калькулятора — `sheet_price_single`.
- Совместимость контракта заказа: `components.materialId + qtyPerItem` сохраняется, меняется только корректность расчета `qtyPerItem`.
- Roll-first модель: для рулонных операций используется `consumption_mode=roll_feed` и `meter_basis=feed`.

## Этапы (квартал)

### Этап A — Консолидация сервисов

- Выделить единый слой warehouse read-model (остатки, резервы, value-метрики).
- Перевести legacy-пути (`backend/src/services/*warehouse*`) на модули `backend/src/modules/warehouse/services/*`.
- Убрать дублирующие SQL-агрегации в старых сервисах, оставить адаптеры совместимости.

### Этап B — Multi-warehouse эксплуатационный UI

- На уровне UI добавить явный выбор склада для прихода/списания/корректировки.
- В карточке материала показывать остатки по каждому складу и суммарный остаток.
- Добавить поток перемещений между складами (`source_warehouse_id -> target_warehouse_id`) как отдельный тип движения.

### Этап C — Lot tracking (партии/рулоны)

- Ввести `material_lots` (опционально по feature-flag):
  - `material_id`, `lot_code`, `received_at`, `quantity`, `remaining_quantity`, `purchase_price`.
- Для рулонов поддержать идентификацию намотки и ширины партии.
- В списаниях поддержать FIFO по лотам с трассировкой в `material_moves.metadata`.

### Этап D — Консолидация аналитики

- Общие метрики (ABC, turnover, stock cover, supplier analytics) считать одним сервисом витрин.
- Для отчетов использовать только детерминированные формулы из движений, без синтетики.
- Разделить read-эндпоинты:
  - `warehouse-reports` — оперативные отчеты;
  - `materials-analytics` — BI-витрины и тренды.

## Технический бэклог

- Ввести versioned DTO для отчетов (`v1`) и контрактные тесты на поля ответа.
- Добавить интеграционный тест: заказ с рулонной ламинацией -> корректный `components.qtyPerItem` -> корректный резерв/списание.
- Добавить тесты миграций для `consumption_mode` и `meter_basis`.

## Метрики готовности

- 100% операций прихода/списания пишут `material_moves.price`.
- Для рулонных услуг `roll_feed` списание расхода совпадает с feed из раскладки (расхождение <= 0.01 м).
- Отчеты склада и материалы аналитики возвращают одинаковые агрегаты за один период.
